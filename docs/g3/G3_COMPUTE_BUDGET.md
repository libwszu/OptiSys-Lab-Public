## 3. 本轮预算上限

| 任务 | 预算 | 说明 |
|---|---|---|
| 全量 `pytest` | ≤ 300 s | G2 历史 128.6 s，G3 新增测试后按 1.5–2× 估 |
| G3 demo run | ≤ 240 s wall | 单进程；面板规模在 `configs/g3_demo.yaml` 冻结 |
| G2 完整明细重算（126 000 行） | ≤ 120 s | 纯 CSV 解析 + numpy 聚合 |
| G2 分层面板重算 | ≤ 600 s | 200 装配 × 7 距离 × 2 条件 × 3 估计器 |
| Streamlit 启动 + 首屏 | ≤ 30 s | 冷启动单次 |
| 审计 ZIP 构建 | ≤ 180 s | 含完整 25.9 MB 明细压缩 |

**硬约束**：任何单次操作超过 600 s 即停止并降级，不在本轮启动
2000×7×多估计器的 G2 全量复跑。

## 4. 并行策略

- 默认 **单进程**。
- 小批量实测 1/2/4 进程，只有在同种子、同结果、加速 ≥ 1.3× 且 RSS 安全时才允许
  在 demo 中使用并行。
- 历史 G2 的 "4 worker 最优" 不作为 UI 默认。
- 限制 BLAS/OpenMP 线程数，避免与进程池嵌套竞争。

## 5. RAM 策略

- 软上限：进程树 RSS 峰值 ≤ 8 GB（机器 31.4 GB，为 OS + UI + 留余地）。
- 用 `psutil` 采样父子进程 RSS；采样失败写 `UNKNOWN`，禁止估算冒充实测。

## 6. 缓存

- 只缓存光路追迹与核生成，cache key 至少含：光学参数、焦距、波长、库版本、
  网格、数值后端、单位。
- 不跨参数复用核。

## 7. 降级顺序（预算不足时）

1. 降低图分辨率（不改数据）；
2. 缩小 demo 样本数（新 run 明示 N）；
3. 推迟 PDF 导出与演示视频。

**不得**削减：失败记录、原始科学证据、测试真实性、manifest 覆盖范围。
